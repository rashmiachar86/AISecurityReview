Credential Exposure

Secret Sprawl & Exposure Patterns

Git History Exposure

Secrets committed to .env files, config, test files, or IaC templates remain in git history even after deletion.

Tools: GitLeaks, TruffleHog, git-secrets, pre-commit hooks, GitHub Secret Scanning

Container Image Secrets

Credentials embedded in container images via ENV vars in Dockerfile, copied config files, or unremediated build-time secrets in image layers.

Tools: Trivy, Grype, Clair — layer-by-layer analysis; registry scanning; admission controllers

Cloud Metadata SSRF

SSRF vulnerabilities in web apps used to query AWS IMDS, Azure IMDS, or GCP Metadata Server for short-lived IAM credentials.

Mitigate: IMDSv2 (session-based), network policies, least-privilege IAM roles, app-level SSRF protection

Configuration File Exposure

Secrets in config.yaml, settings.json, .env files in production, or database connection strings accessible to unauthorized parties.

Remediation: Secrets management systems (Vault, AWS SM), encrypted configs, access control enforcement

Log File Leakage

API keys, tokens, and connection strings inadvertently logged to app logs, web server logs, or error messages — then accessible via log aggregation platforms.

Remediation: Log sanitization, secret redaction, structured logging patterns, developer guidelines

Private Registry Credential Sprawl

Package registry tokens (npm, PyPI, Maven) stored in multiple places — CI configs, developer machines, shared secrets — without rotation policies.

Remediation: Centralized secrets management, short-lived tokens, SBOM signing and verification
